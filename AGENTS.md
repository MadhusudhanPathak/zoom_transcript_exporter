# AGENTS.md

Context for LLM coding agents (and human contributors) working on this repository. Read this before changing code. The user-facing docs are [README.md](README.md) and [PRIVACY.md](PRIVACY.md). The original design brief is [docs/blueprint.md](docs/blueprint.md); where this file and the blueprint disagree, this file wins.

## What this is

A Manifest V3 Chromium extension (Edge, Chrome, Brave) that exports the transcript panel of a Zoom cloud recording page to a `.txt` file. Zoom's transcript panel is a virtualized list, so only rows near the viewport exist in the DOM. The extension scrolls the panel step by step, snapshots the rendered text, merges overlapping snapshots, and downloads the result.

It began as a console script the maintainer ran successfully. The extension had to reproduce that script's output exactly (see `runReferenceScript` in the e2e spec, and the parity test).

## Hard rules (don't break these)

1. **Zero network requests.** No `fetch`/XHR/WebSocket/beacons, no remote scripts, fonts or CDNs, no analytics. The e2e harness fails any test that makes a request outside the fixture origin, and `tests/unit/manifest.test.js` greps for network APIs and `eval`.
2. **Minimal permissions:** exactly `["activeTab", "scripting"]`. No `host_permissions`, `storage`, `downloads`, `tabs`, background worker or content scripts. A unit test enforces this. The header preference lives in the popup page's own `localStorage`, which needs no permission.
3. **No `eval` / `new Function` / remote code** (MV3 policy, and the CSP blocks it in extension pages anyway).
4. **Output parity.** With the header off, the file is the transcript lines joined by `\n`, byte-identical to the reference console script on the same page.
5. **Never write passcodes to files.** `Source:` in the header uses `cleanSourceUrl()`, which drops the query and fragment (Zoom links carry `?pwd=…`).
6. **Plain JS, no build step.** `extension/` must load unpacked as-is. Dev dependencies are for tests only.
7. **Read-only on the page.** It only reads rendered text. It doesn't bypass auth and doesn't touch the video or audio.

## Layout


## Runtime architecture

1. **Popup** (`popup.js`). It classifies the tab URL; browser-internal pages and web stores get the buttons disabled.
   - **Export transcript** runs `exportFromTab(tab, {header})`:
     1. Inject `lib/text.js` and `extractor.js` into all frames (`allFrames: true`).
     2. Probe every frame with `__zte.detect()`.
     3. If any frame reports `running`, return `running`.
     4. Otherwise rank the hits by `scrollHeight`, then timestamp count, and call `__zte.start({title, url, header})` in the best frame only (`frameIds: [id]`).
   - **Select transcript manually** runs `pickFromTab()`, which calls `__zte.startPicking(opts)` in all frames.
   - `title` and `url` come from the tab, so they're correct even when the transcript is in an iframe.
   - Both functions are top-level declarations, so the e2e tests can call them from the popup page.
2. **Extractor** (`extractor.js`, isolated world, one instance per frame, guarded by `if (globalThis.__zte) return`).
   - `window.__zteRunning` allows one job per frame (double clicks, a second popup, pick mode during an export).
   - The work runs in the page, so the popup can close. UI is an in-page overlay in a **Shadow DOM** (`#zte-overlay-host`; pick mode uses `#zte-picker-host`), so Zoom's CSS and ours can't clash.
3. **Panel detection** (`findTranscriptPanel`): `overflow-y: auto|scroll`, `scrollHeight > clientHeight + 200`, `clientHeight < innerHeight` (excludes the page scroller), and `innerText` matches `/\d{1,2}:\d{2}/`. Rank by **scrollHeight first**, timestamps as tie-break. The blueprint's §5.1 said the opposite, but timestamp-first lets an outer wrapper beat the virtualized list.
4. **Extraction loop** (`extractTranscript`, tuned by `CONFIG`):
   - **Step:** 70% of `clientHeight`. Scroll with `scrollTo({behavior: 'instant'})`, because CSS smooth scrolling would otherwise look like being stuck.
   - **Waiting:** `waitForRender` resolves after the first DOM mutation followed by 80 ms of quiet, or after 1.5 s. It watches childList/characterData, not attributes, because Zoom toggles highlight classes. After 3 scrolls with no mutation it switches to a 250 ms "fast mode" (non-virtualized lists).
   - **Merge:** `findOverlap` (longest suffix of the output that equals a prefix of the snapshot) is behaviourally identical to the reference script. A randomized unit test proves it.
   - **Gap guard:** if the overlap is 0 while the output is non-empty, rows were skipped. Scroll back halfway and re-read (up to 3 times). This is what makes lazy rendering work.
   - **End conditions:** at the bottom (within 5 px), after a patient final snapshot, continuing if the list grew; `scrollTop` unchanged after a scroll; 5,000 steps; or cancel (an `AbortController` that also interrupts waits).
   - **Hidden tab:** pause while `document.hidden` and resume on `visibilitychange`, then settle again before snapshotting. Browsers don't render background tabs, so snapshots there are stale.
   - **Finish:** restore the original `scrollTop` in `finally`.
5. **Overlay:** lines, percentage, progress bar, a bold "keep this tab open" warning (red "Paused" variant), and "Time taken / Time left".
   - The time-left estimate is linear extrapolation over *active* time (pauses excluded) and stays null until 2% progress and 2 s.
   - Cancel shows "Export cancelled." with an opt-in **Save N lines** button. A partial save gets a `Note:` header line.
   - The overlay auto-dismisses after a few seconds.
6. **Pick mode:** runs in every frame.
   - Hover outlines the innermost vertically-scrollable ancestor (`scrollableAncestor`, which crosses shadow roots and never returns html/body).
   - Capture-phase listeners swallow page clicks and pointer events, except on our own host.
   - The instruction banner appears only in the top frame.
   - Ending pick mode (pick, Esc or Cancel) is broadcast with a data-free `postMessage('__zte_pick_end__')`: up to `window.top`, and relayed down to child frames.
7. **Saving:** `buildFileText` adds the optional header (`buildHeader` in lib).
   - The **Recorded** date comes from `findRecordedDate`: a TreeWalker over text nodes outside the panel and our own hosts, returning the first `findDateInText` match.
   - The download is a Blob URL and a **detached** `<a download>` click, so page click handlers can't intercept it. The URL is revoked after 10 s.
   - Filename: `<sanitized tab title> - transcript.txt`, falling back to `transcript.txt`.

## Testing

```sh
npm test            # unit (node:test)
npm run test:e2e    # Playwright (headless Chromium, channel 'chromium' = full build, needed for extensions)
npm run test:all
HEADED=1 npm run test:e2e
```

- If Playwright says the browser executable is missing, run `npx playwright install chromium`. Each Playwright version pins a Chromium revision.
- **Harness trick:** automation can't click the toolbar button, so `activeTab` is never granted. The e2e fixture copies `extension/` to a temp dir and adds **test-only** `host_permissions: ["http://zte.test/*"]` plus an empty `background.service_worker`. The worker is there only so the test can read the extension ID. The shipped manifest is never modified.
- Tests then open `chrome-extension://<id>/popup.html` and call `exportFromTab` / `pickFromTab`.
- **Network:** `context.route('**/*')` serves fixtures for `http://zte.test`, lets `chrome-extension:` through, and records everything else as a violation that fails the test.
- **Header:** the helpers `clickExport` and `clickPick` default to `header: false`, so files can be compared to `window.fixture.expectedLines()` exactly. The header has its own test.
- **Fixture query parameters** (`virtual-list.html`):

  | Parameter | Values |
  | --- | --- |
  | `variant` | `basic`, `repeated`, `lazy`, `plain`, `empty`, `none` |
  | `count` | number of entries |
  | `delay` | lazy render delay in ms |
  | `smooth=1` | panel uses smooth scrolling |
  | `ts=0` | no timestamps (forces pick mode) |
  | `chat=0` | no decoy chat |

  The page header contains "Nov 12, 2026 09:58 AM" for the Recorded test. A decoy chat scroller with times exists unless `chat=0`.
- **Gotchas learned the hard way:**
  - Headless Chromium never sets `document.hidden` for background tabs, so the pause test overrides `document.hidden` in the isolated world via `chrome.scripting.executeScript` and dispatches `visibilitychange`.
  - A non-front tab in headless still gets throttled rendering. Call `page.bringToFront()` after using the popup page, or exports slow to a crawl (correct output, roughly 6× slower).
  - `context.route` also intercepts `chrome-extension://` requests; continue them.
  - Don't use `eval` in `popup.evaluate` callbacks to build helpers: the extension page's CSP blocks it.
- Unit tests cover the overlap merge (including a randomized comparison against the reference implementation), filename sanitizing, duration and ETA formatting, URL cleaning, date finding, timestamp span, header layout, and manifest/policy checks.

## Releases

- The version lives in `extension/manifest.json`. Keep `package.json` in sync. Currently **1.0.0**, not yet published to GitHub when this was written.
- To release:
  1. Run `npm run package`. It writes `Release/zoom-transcript-exporter-<version>.zip` (the extension files plus `LICENSE`, with fixed timestamps so builds are reproducible), writes `Release/SHA256SUMS.txt`, and deletes older zips.
  2. Update `Release/RELEASE_NOTES.md`.
  3. Draft a GitHub release with the tag `v<version>`, and attach the zip and the checksum file.
- The license is **GPL-3.0-only** (`LICENSE` is the verbatim FSF text). The zip must include `LICENSE`.
- Repository: <https://github.com/MadhusudhanPathak/zoom_transcript_exporter>

## Decisions that differ from the blueprint

- The extension lives in `extension/`, not the repo root, so `node_modules` and tests stay out of the unpacked folder and the zip. Shared helpers are `lib/text.js`, not `lib/overlap.js`.
- Panel ranking is height first (see above).
- The mutation wait is "first mutation, then quiet", plus fast mode, not "first mutation".
- The gap guard is new. The reference script loses most lines on the lazy fixture, and a test documents this.
- Repeated lines use the reference's longest-overlap merge, unchanged. Identical consecutive entries survive while the true snapshot overlap is longer than the run of identical lines. A run of identical entries (same speaker, timestamp and text) taller than about 30% of the panel would collapse. That's accepted, because it doesn't occur in real transcripts.
- Cancel keeps the overlay briefly, with an opt-in partial save, instead of removing it instantly.
- No Zoom-specific selector fast path. No `stripTimestamps()` stub.
- The popup is enabled on any normal web page (with a "doesn't look like Zoom" hint); detection is generic.

## Conventions

- Comment the *why* for anything non-obvious (merge, waits, Shadow DOM, pause, pick-mode messaging).
- Put new pure logic in `lib/text.js` with unit tests. DOM and page logic go in `extractor.js` and are covered by an e2e test with a fixture variant.
- Keep user-facing messages plain and specific. The popup messages live in `POPUP_MESSAGES`, the overlay messages in `MESSAGES` and the overlay code.
- Run `npm run test:all` before declaring work done. The e2e suite takes about 40 s with parallel workers.
